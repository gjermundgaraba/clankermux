# clankermux implementation plan

Companion to `PROTOCOL.md`. The last milestone deletes this file.

## Decisions

- Rust server and CLI client in one binary, `clankermux`. TypeScript browser
  client. Both clients ship in version 1.
- libghostty-vt is pinned to one upstream `main` commit at or after
  2026-10-11, the first with both `PROGRAM_STATUS` (2026-10-06) and
  `RESIZE_WINDOW` (2026-10-11). Source is the per-commit archive
  `https://tip.files.ghostty.org/<sha>/libghostty-vt-source.tar.gz`,
  verified by a recorded sha256 and vendored under `vendor/libghostty-vt/`.
  The archive does not vendor Zig packages: they are fetched once at pin
  time into `vendor/zig-deps/`, and every build runs with `--system`.
- Zig 0.16.0 is a build dependency on every machine that builds the engine.
- Engine id is `ghostty-vt@<sha>`. The native library and `ghostty-vt.wasm`
  are built from the same vendored tree by one script. CI proves the wasm
  decoder accepts what the native encoder produces.
- Bindings are bindgen output committed to the repo and regenerated by a
  task, never at build time.
- PTY layer is hand-written on `rustix` and `libc`: `openpty`, fork, exec
  with `setsid`, process group, `waitpid` separate from master EOF. The
  signal fallback to every PTY-slave holder uses libproc on macOS and
  `/proc/*/fd` on Linux.
- Runtime is tokio, multi-thread. Engine calls (`vt_write`, resize, snapshot
  encode, formatter) run on the session's own OS thread, never on the
  executor.
- `TCP_NODELAY` on every stream socket. TCP stays plaintext on the tailnet.
- Browser carrier is WebSocket over TLS, one frame per binary message. The
  daemon serves no static files; the page is hosted separately and its
  origin is configured in the allowlist. Certificate and key come from
  `--tls-cert` and `--tls-key`, or from the Tailscale local API
  `/localapi/v0/cert/<domain>?type=pair&min_validity=<dur>` (key PEM first,
  then certificate), renewed on a timer, 429 honoured via `Retry-After`.
- CLI client passes PTY bytes straight to the outer terminal while the outer
  size equals the session size. When sizes differ it repaints from its local
  engine through the formatter, clipped to the outer terminal, until they
  match again. It drops the outer terminal's answers to the program's queries
  by expectation: the local engine's write-to-PTY effect names each answer
  the server will send, and the next response of that shape on stdin is
  consumed instead of forwarded. `PROTOCOL.md` should state this client
  duty; proposed, not yet applied.
- Browser renderer is our own, Canvas 2D over the engine's render state,
  parsing in a worker. gespenst (MIT) is the reference, not a dependency.
- Reconnect with `resume` is a milestone in both clients, not a follow-up.

## Server

- Connection: one task per connection; framed reader enforcing
  `limits.max_frame`; writer fed by a bounded channel; `hello_timeout`;
  channel table; `protocol_error` closes the connection.
- Session: one OS thread owns the terminal and the PTY master. Loop: read
  PTY, `vt_write`, append to the ring, publish the new offset. Input from a
  bounded queue of `limits.input_queue` bytes, each frame written whole.
- Stream: ring of `limits.ring` bytes with lifetime offsets; marker deque
  bounded by `limits.markers`. Each attachment pulls from its cursor; a
  cursor behind the ring start is a `GAP`.
- Attach: under the session lock take the cut and encode the snapshot into a
  buffer, then unlock. Walk the record headers to find the end of `READY`,
  send `SNAPSHOT` to there, `SNAPSHOT_READY`, then interleave the stream with
  the remaining snapshot bytes, stream frames first.
- Effects: write-to-PTY to the input queue; program status to the record
  store; semantic prompt clears working and blocked; colour scheme answers
  from the authoritative profile; clipboard and resize-window effects
  dropped.
- Size: 25 ms coalescing timer per session; latest wins; immediate reports
  cancel the timer; mode 2048 and 2031 reports written to the PTY.
- Exit: a reaper thread on `SIGCHLD`; drain the PTY to EOF; append
  `EXITED`; `remove_grace` timer; removal closes attachments.
- Park: generation directory, temp dot-dir, fsync files and directory,
  rename, fsync parent, delete older. Five-minute timer, graceful stop,
  `SIGHUP`. Lock file. Load at start, engine compared before any attach.
- Carriers: Unix socket with peer uid from `SO_PEERCRED` or `LOCAL_PEERCRED`;
  TCP bound to the address from `/localapi/v0/status?peers=false`; TLS
  WebSocket with `tokio-tungstenite` and `tokio-rustls`, `Origin` checked
  before upgrade; `--stdio` relaying to the Unix socket.

## CLI client

- Raw mode, outer size from the terminal, `HELLO` with the engine id, `OPEN`
  with viewport and profile.
- Bootstrap: buffer snapshot bytes to `SNAPSHOT_READY`, decode to `READY`,
  paint the screen through the formatter, then pass `OUTPUT` through. Decode
  history one step at a time as bytes arrive. Hold stream frames after a
  `RESIZED` until `SNAPSHOT_END`.
- Input: stdin split into whole key encodings, one `INPUT` per frame, with
  the expectation filter from Decisions. `SIGWINCH` sends `VIEWPORT`.
- Resize: apply `RESIZED` at its offset; switch between passthrough and
  repaint as sizes match or differ.
- Reconnect: on connection loss retry with backoff and `resume`; fall back
  to a fresh bootstrap on `snapshot` or `GAP`.
- Exit: print status on `EXITED`; detach key restores the outer terminal.

## Browser client

- WebSocket binary messages, one frame each, same header parser as the TS
  proto package.
- Engine in a worker: wasm loader, decoder stepping identical to the CLI,
  `OUTPUT` fed to `vt_write`, render state read into a shared buffer for
  the main thread.
- Renderer: Canvas 2D, dirty rows only, cursor, selection later.
- Keyboard through the engine's input encoder; `ResizeObserver` sends
  `VIEWPORT`; clipboard effect to `navigator.clipboard`.
- Reconnect with `resume` as in the CLI. Engine id injected at build from
  `vendor/PIN`.
